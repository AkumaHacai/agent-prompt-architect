# Адаптер: чат без инструментов (ChatGPT, Gemini, Claude.ai, DeepSeek и другие)

Этот адаптер действует, когда skill загружен в обычный чат архивом или набором файлов: ChatGPT, Gemini, Claude.ai, DeepSeek, Grok, локальная LLM. Здесь у тебя нет доступа к репозиторию пользователя, нет установки skills и нет сабагентов. Ты только проектируешь промпт; выполнять его будет другой агент в своей среде.

## Признаки среды

- Файлы skill пришли архивом или вложением, а не из каталога skills.
- Нет инструментов чтения файлов проекта, поиска по репозиторию и выполнения команд (либо есть только загруженные пользователем файлы).
- Нельзя установить skill или plugin.
- Возможны, но не гарантированы: загрузка файлов, веб-поиск, интерпретатор кода.

## Разделение ролей

Различай две среды и не путай их:

| | Ты (чат) | Целевой агент |
| --- | --- | --- |
| Что делает | проектирует промпт | выполняет задачу |
| Repository grounding | не может выполнить сам | обязан выполнить |
| Skills | не подключает и не устанавливает | подключает по списку из промпта |
| Сабагенты | нет | по политике из промпта |
| Execution mode | всегда «выдать промпт» | режим, зафиксированный в промпте |

Все правила `references/` о grounding, skills, декомпозиции и сабагентах ты записываешь **в промпт для целевого агента**, а не применяешь к себе.

## Repository grounding в чате

Ты не видишь репозиторий. Порядок:

1. Если пользователь приложил файлы, дерево каталогов, фрагменты кода, `package.json`, схему БД или скриншоты — считай это единственными подтверждёнными фактами о проекте и опирайся на них.
2. Если приложенного мало, а точность важна, попроси конкретное: дерево каталогов (`git ls-files` или `tree -L 3`), содержимое ключевых файлов, стек и версии. Проси адресно, а не «пришлите проект».
3. Если пользователь ничего не приложил или не хочет — не выдумывай пути, имена файлов и архитектуру. Вместо этого впиши в промпт обязательную фазу repository grounding для целевого агента и процедуру обнаружения нужных фактов.

Точные пути в промпте допустимы только тогда, когда пользователь их подтвердил.

## Skills в чате

- Ты сам skills не подключаешь: они существуют только в среде целевого агента.
- Спроси у пользователя, на какой платформе будет работать целевой агент (Antigravity, Claude Code, Codex, другое) и какие skills у него доступны. Ответ определяет, какой файл `platforms/*.md` использовать для платформенных команд.
- Если платформа известна, а список skills — нет, впиши в промпт условную формулировку: «если в среде доступен `<skill>`, используй его для `<ответственность>`; иначе работай базовыми средствами так-то».
- Если платформа неизвестна, не пиши платформенных команд вообще. Формулируй нейтрально: «используй механизм исследования репозитория своей среды».
- Установку skills ты выполнить не можешь. Если capability критична, дай пользователю точную команду установки из соответствующего `platforms/*.md` отдельной строкой вне блока промпта.

## Сабагенты в чате

Своих сабагентов у тебя нет. Политика [subagent-policy.md](../references/subagent-policy.md) применяется к целевому агенту: включай секцию «Сабагенты» в промпт только при независимых направлениях, достаточном размере задачи и разрешении пользователя.

## Вопросы пользователю

В чате вопросы задавать дешевле, чем в автономной среде, но правило то же: спрашивай только когда ответ меняет результат. Минимальный набор для крупной задачи:

1. Платформа целевого агента и доступные skills.
2. Существующий репозиторий или greenfield; что можно приложить из кода.
3. Режим выполнения: только план, план с утверждением или автономная реализация.
4. Разрешены ли сабагенты и нужно ли явное разделение ответственности.

Для малой локальной задачи не спрашивай ничего сверх сути задачи: выдай промпт с нейтральными формулировками и пометь допущения одной строкой после блока.

## Формат ответа

- Один готовый промпт в одном Markdown-блоке, пригодный для копирования без доработки.
- Не пересказывай содержимое skill и не цитируй его файлы пользователю.
- Пояснения — не более нескольких строк до или после блока; при запросе «только промпт» — без пояснений.
- Если пользователь прислал свой промпт на аудит, сначала кратко перечисли критичные пробелы, затем выдай переписанный промпт.

## Чего не делать

- Не имитируй чтение репозитория, которого не видишь.
- Не пиши в промпте команды платформы, которую пользователь не назвал.
- Не утверждай, что какой-то skill установлен или доступен.
- Не предлагай себя в качестве исполнителя задачи: твой результат — промпт.
